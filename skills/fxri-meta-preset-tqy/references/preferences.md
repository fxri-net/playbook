# 个人偏好详解

## 沟通

- 开头直接给结论或下一步动作；背景只在必要时补一句。
- 不确定时明确说「不确定」并给验证方式，不猜。
- 方案对比放在末尾，且包含前文未单独提到的判断结论。

## 执行

- 改动前先读相关文件与约定；不基于未读代码提方案。
- 一次只做被要求的事；不顺手重构、不扩大范围。
- 失败先定位原因，不重复重试同一动作。
- 交付前跑项目统一的验收命令；失败先修复再交付。

## 代码

- 注释全中文，解释「为什么」；变量与函数按项目既有风格命名。
- 共享工具函数沿用项目已有前缀，不另起一套。
- 不留「先这样、后来改成那样」的过程性注释。
- 新增依赖前先确认项目是否已有等价能力。

## 文本与文件

- `.ps1` 用 UTF-8 with BOM；`.sh` 无 BOM + LF；`.bat` / `.cmd` 无 BOM + CRLF。
- 生成或转码文本后自查首三字节与行尾，不只改产物不修产线。
- 仓库内引用用仓库根相对路径，不写本机绝对路径。

## 任务

- 多任务先给纯展示计划表，再逐仓逐任务建档。
- 每个任务完成即归档、验收、提交，不跨任务攒批。
- 收尾时把可复用结论沉淀为规范，一次性决策留在任务正文。
