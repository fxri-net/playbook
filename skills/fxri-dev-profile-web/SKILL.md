# Web 前端开发规范

> 本技能版本 0.1.0（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 新建或修改页面、组件、样式与前端交互时
- 评审前端代码、排查可访问性 / 性能 / 兼容问题时
- 需要给团队制定通用前端基线时

不用于：具体框架的组件模式（见对应框架 profile）、后端契约设计、纯视觉设计稿评审。

## 核心原则

1. **语义先行**：能用原生元素表达的结构不用 `div` 模拟；标题层级、表单标签、按钮语义保持完整。
2. **可访问性默认开启**：键盘可达、焦点可见、颜色对比达标、图片有替代文本、动态内容有播报。
3. **渐进增强**：核心内容与导航在脚本失败时仍可用；交互增强不阻断基础流程。
4. **性能预算**：首屏只加载必要资源；图片按需与响应式加载；避免长任务阻塞主线程。
5. **安全默认值**：外部输入只当文本处理；拼接 HTML 前先转义；链接外跳带 `rel="noopener noreferrer"`。
6. **兼容有据**：按项目声明的浏览器范围决定 polyfill，不凭印象引入整包垫片。
7. **样式可维护**：命名与层级有约定；避免深层选择器与 `!important` 兜底；状态样式集中管理。

## 工作流程

1. 先确认目标浏览器、性能预算与可访问性等级。
2. 用语义结构搭骨架，再补样式与交互。
3. 用键盘与屏幕阅读器路径自测，再跑性能面板与兼容检查。
4. 提交前检查控制台无报错、无未处理 Promise、无布局抖动。

## 检查清单

- [ ] 标题层级连续，表单控件有关联标签
- [ ] 所有交互可用键盘完成，焦点样式可见
- [ ] 图片有 `alt`，装饰图用空 `alt`
- [ ] 首屏资源与图片尺寸有预算并达标
- [ ] 用户输入在输出前转义或按文本节点渲染
- [ ] 目标浏览器范围内无未处理的语法 / API 差异

详细判据与反例见 `references/principles.md`。
