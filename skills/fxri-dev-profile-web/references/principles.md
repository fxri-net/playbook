# Web 前端原则详解

## 语义与可访问性

- **结构**：`header` / `nav` / `main` / `section` / `footer` 按内容职责使用；一页只保留一个 `main`。
- **标题**：从 `h1` 起连续，不用标题控制字号；视觉层级交给样式。
- **表单**：每个控件有可见标签；错误提示与控件通过 `aria-describedby` 关联。
- **键盘**：自定义下拉、弹层、拖拽须提供键盘等价操作；打开弹层后焦点进入弹层，关闭后归还触发元素。
- **对比度**：正文文本对比度至少 4.5:1，大号文本至少 3:1；不仅靠颜色传达状态。
- **动态内容**：异步更新区域用 `aria-live` 适度播报，避免整页刷屏。

反例：用 `div` + `onclick` 模拟按钮，导致键盘不可达、屏幕阅读器不识别。

## 性能

- 首屏只加载必要 CSS/JS；非关键脚本延迟加载。
- 图片给出宽高比，避免布局偏移；按视口选择尺寸，首屏图优先加载。
- 长列表使用分页或虚拟滚动；避免在主线程做大规模同步计算。
- 动画优先使用 `transform` / `opacity`，避免触发布局与重绘。
- 用真实设备或节流网络复测，不以开发机桌面环境代替。

## 安全

- 用户输入默认按文本渲染；必须拼接 HTML 时先做上下文相关转义。
- 外跳链接带 `rel="noopener noreferrer"`；`target="_blank"` 不单独使用。
- 不把敏感信息写入前端代码、URL 查询串或日志。
- 第三方脚本按最小权限引入，评估其网络与存储访问范围。

## 兼容

- 以项目声明的浏览器范围为准；范围外不承诺。
- 新 API 先查兼容表，再决定特性检测、降级或 polyfill。
- 不因单个旧浏览器引入整包垫片；按需引入并记录原因。

## 样式维护

- 命名与层级遵循项目既有约定；新约定先写进项目文档再落地。
- 避免三层以上选择器与全局 `!important`；覆盖样式用更高特异性或作用域方案。
- 状态样式（hover / focus / disabled / loading / error）集中定义，避免散落。
