# 接口契约与数据展示示例

> 配合 `SKILL.md` 使用。每条先给正例，再给反例与后果。

## 1. 码值映射中文再展示

- 正例：接口给 `spaceLevel: "COUNTRY"`，页面映射表写 `{ COUNTRY: "国家级", PROVINCE: "省级", CITY: "市级" }`，取值写 `映射表[值] ?? 值?.name ?? ""`。
- 反例：页面直接渲染 `spaceLevel`，用户看到 `COUNTRY`；未知码值时不兜底，界面出现 `undefined`。

## 2. 枚举与字典来源三级确认

- 正例：地区筛选先查同族页面是否已有字典调用，有则复用；没有则接后端字典接口，选项文本与提交值同取字典全称。
- 反例：页面里写死区县数组（且用简称），提交值与库内全称对不上，字典新增区县时前端还要跟改。

## 3. 契约与需求不一致先咨询

- 正例：界面需要「审核人」字段但返回结构没有，先说明字段位置与用途，由开发者确认是补字段、换接口还是去字段；未定前隐藏该行并记录假设。
- 反例：前端自行拼装一个近似字段并固化为默认实现，后续无人知道它与真实口径无关。

## 4. 运行期与契约不符不自适配

- 正例：端点返回非标准结构，前端仍按契约取值，现象记录为上游问题并交上游修；不改全局响应层。
- 反例：在响应拦截器里兼容扁平结构，放宽成功判定，掩盖系统性缺陷。

## 5. 响应信封以运行时为准

- 正例：类型声明多一层信封，先用真实请求确认运行时层级，再按实测层级取值，类型侧用收口断言表达。
- 反例：照类型逐层取值，运行时该层为空，列表恒空且控制台无报错，排查成本极高。
