# 接口契约与数据展示规范

> 本技能版本 0.1.1（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 接口返回码值、字典键，需要决定怎么呈现、从哪里取选项
- 接口契约与界面需求有落差，需要决定由谁改、怎么兜底
- 运行期响应与生成类型不一致，需要决定以哪边为准

不涉及：设计稿还原（见 `fxri-code-profile-restore`）、代码组织约定（见 `fxri-code-profile-web`）。

## 通用说明

每条规则带「适用前提」与「项目无对应物」两段，前提不成立即整条跳过。映射表、字典接口与响应拦截器的具体形态见 [适配表](./references/adapters.md)，示例与反例见 [原则示例](./references/principles.md)。

## 规则

### 1. 码值映射中文再展示

- **适用前提**：接口返回枚举或字典类码值，界面需要呈现可读文本。
- **要求**：渲染前经本地映射表把码值转成可读文本，不把码值原样输出；取值用「映射优先 + 原值兜底」，既兼容上游直接给文本或对象形态，也不因未知码值渲染出空占位。
- **项目无对应物**：项目没有既有映射表时，在离使用处最近的位置建表，并沿用同族页面的命名与结构。
- **反例**：页面直出全大写下划线码值；未知码值不兜底，界面出现空串或占位符。

### 2. 枚举与字典来源三级确认

- **要求**：按顺序确认——① 同族页面或公共模块已有同义枚举，直接复用；② 后端有对应字典接口，取接口，前端不写死；③ 都没有，向开发者确认来源。后端未就绪时可临时用本地数组并标注，就绪后回迁字典接口、不改页面结构。
- **反例**：不问来源就直接写死选项数组定稿；后端已有字典接口仍另立本地枚举，造成两端取值不一致。

### 3. 契约与需求不一致先咨询

- **要求**：缺字段、缺操作接口、字段形态不符三类，先向开发者说明现状与所需，由开发者定口径。未定前可暂用占位、隐藏该行、点击提示未开放，但不固化为默认；不因缺字段自造前端拼装，不因缺接口删除已还原控件。
- **反例**：接口未就绪即自作主张写死前端方案并固化，事后无人知晓这是临时兜底。

### 4. 运行期与契约不符不自适配

- **适用前提**：运行期响应结构与生成契约不一致。
- **要求**：按契约实现，现象归属上游、交由上游修；不在页面侧或全局响应层兜底，不放宽全局成功判定。
- **项目无对应物**：无生成契约的项目按实测结构实现，并把实测结论写进任务档。
- **反例**：在全局响应层兼容非契约结构，掩盖系统性缺陷并污染全局响应规则。

### 5. 响应信封以运行时为准

- **适用前提**：生成类型声明比运行时多一层信封（统一响应体被拦截器解过一层）。
- **要求**：取值以运行时实测结构为准；类型侧用收口断言表达，不按类型逐层取值；类型与运行时不一致时先实测再定写法。
- **反例**：照类型声明写多层取值，运行时该层为空，列表恒空且无任何报错。

## 检查清单

- [ ] 页面未直出码值，码值均有映射且带兜底
- [ ] 选项来源按「复用 → 字典接口 → 问人」顺序确认
- [ ] 契约落差已向开发者确认，临时兜底已标注
- [ ] 未在全局响应层为不符契约的结构做适配
- [ ] 取值层级与运行时实测一致
