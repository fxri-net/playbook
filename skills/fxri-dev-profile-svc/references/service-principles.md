# 服务端原则详解

## 契约

- 入参、出参、错误码、状态码、幂等语义在契约中写明；实现与契约不一致视为缺陷。
- 新增字段保持向后兼容；删除或改语义须走版本化与迁移窗口。
- 错误码稳定且可检索，不用自然语言当错误码。

反例：接口直接返回数据库异常文本，调用方无法区分「参数错误」与「服务故障」。

## 校验与权限

- 类型、长度、范围、枚举在入口校验；校验失败返回明确错误码。
- 权限检查在服务端完成，不依赖前端隐藏入口。
- 内部调用信任已校验的数据，不重复做边界校验，但保留关键不变量检查。

## 幂等

- 创建类接口使用客户端生成的幂等键；重复请求返回同一结果。
- 消息消费按消息 ID 去重；处理失败可重试且不产生重复副作用。
- 幂等键有有效期与清理策略，避免无限增长。

## 事务与一致性

- 事务只包住必要写操作；网络调用、文件 IO 不放入事务。
- 跨服务一致性用补偿、事件或最终一致；不假设分布式事务可用。
- 并发写有锁、版本号或条件更新策略，避免丢失更新。

## 可观测性

- 日志带请求 ID、用户标识（脱敏）、关键参数摘要与耗时。
- 关键路径有成功率、延迟、错误码分布指标；告警有明确阈值与处置入口。
- 日志不打印密码、令牌、完整身份证 / 手机号等敏感字段。

## 安全

- 查询使用参数化语句；输出按上下文编码。
- 凭据来自环境变量或密钥管理，不写入代码、镜像或日志。
- 外部依赖按最小权限授权，定期轮换凭据。

## 故障隔离

- 外部调用设置连接 / 读取超时与重试上限；重试只用于可重试错误。
- 熔断与降级有明确触发条件与恢复策略。
- 单个依赖故障不阻塞无关路径；批量任务有分片与失败重试。

## 文档

- 接口文档、错误码表、运行手册与实现同批更新。
- 变更契约时通知调用方，保留兼容窗口与回滚路径。
