# Vue 原则详解

## 组合式 API

- 一个组合式函数只解决一件事，返回 `ref` / `computed` / 方法，不返回组件实例。
- 组合式函数内部创建的副作用自行负责清理，调用方不需要了解细节。
- 命名以 `use` 开头，参数与返回值保持可推导的类型。

反例：组件内同时管理请求、分页、筛选、弹层四类状态，导致复用与测试困难。

## 组件边界

- **展示组件**：只依赖 props，输出事件；不直接访问路由、store 或全局单例。
- **容器组件**：负责取数与编排，把数据整理成展示组件需要的形状。
- **业务规则**：放在组合式函数或 store，不散落在模板事件里。

## 响应式

- 同一份状态只保留一个真源；多处副本必然漂移。
- 派生值用 `computed`；只有需要执行副作用时才用 `watch`。
- 避免对同一数据同时使用 `watch` 与 `computed` 做等价转换。
- 解构响应式对象时使用 `toRefs` 或保持引用，避免丢失响应性。

反例：用 `watch` 把 `firstName + lastName` 同步到 `fullName`，再在别处反向同步。

## 状态管理

- 全局状态只放跨页面共享、需要长期存活的数据；页面内状态留在组件或组合式函数。
- store 的 action 负责异步与副作用，getter 只做派生。
- 不把组件实例、DOM 引用放入全局 store。

## 路由

- 路由参数变化时复用组件要显式监听参数，不依赖组件重建。
- 路由守卫只做鉴权与重定向，不承载业务数据加载以外的复杂逻辑。
- 懒加载按页面边界拆分，避免把首屏依赖拆成额外请求。

## 测试

- 组合式函数用独立测试覆盖状态变化与副作用清理。
- 组件测试覆盖关键交互、空态、错误态与禁用态。
- 不测试实现细节（内部 ref 名称、私有方法），测试可观察行为。
