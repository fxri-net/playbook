# Java 原则详解

## 构建与依赖

- Maven：父 POM 或 BOM 统一依赖版本；不在子模块散写版本号。
- Gradle：使用 version catalog；wrapper 入库，构建版本可复现。
- 升级依赖先看变更日志与 CVE；破坏性变更单独提交并附验证结果。

## 分层

- Controller：协议转换、参数校验、权限注解；不写业务分支。
- Service：业务规则与事务边界；对外暴露接口，不暴露实现细节。
- Repository：查询与持久化；复杂查询放 Repository 或专门的 Query 对象。
- DTO 与实体分离：不直接把持久化实体暴露给外部。

## 事务

- `@Transactional` 标在 Service 公开方法；同类内部调用不经过代理，事务不生效。
- 明确传播行为：默认 `REQUIRED`；需要独立事务时显式 `REQUIRES_NEW` 并说明原因。
- 明确回滚条件：默认只对运行时异常回滚；受检异常需显式声明。
- 事务内不做远程调用、文件 IO、消息发送；需要时用事务外补偿或事件。

反例：在事务方法内调用 Feign，远程超时导致数据库连接长时间占用。

## 远程调用

- Feign / HTTP 客户端设置连接超时、读取超时与重试上限；只对可重试错误重试。
- 配置熔断与降级；降级返回值有明确语义，不返回误导性的空成功。
- 调用方与被调方约定错误码；不把底层异常文本直接透出。

## 消息与定时任务

- 消费者按消息 ID 或业务唯一键去重；处理失败进入重试队列或死信队列。
- 消息处理幂等，重复消费不产生重复副作用。
- 定时任务在多实例下用分布式锁或调度平台选主；任务执行有超时与告警。
- 批量任务分片处理，单条失败不阻塞整批。

## 异常与日志

- 业务异常与系统异常分开；对外错误码稳定。
- 日志带 traceId、用户标识（脱敏）与关键参数摘要；不打印密码、令牌、完整证件号。
- 捕获异常后要么处理、要么带上原因重新抛出；不吞异常。

## 空值与可选值

- 对外返回集合时返回空集合而非 `null`。
- 可选值用 `Optional` 表达返回值；不把 `Optional` 用作字段或参数。
- 字符串判空使用工具方法，避免 `null` 与空串两套分支散落。
