# 项目协作规范索引

> 本文件为规范载体唯一入口与唯一权威；规范全貌见下方索引，条文见各分册。
> 读面纪律：`history.md` / `retired.md` 属归档面，仅在审计 / 恢复时读，不在常规读面。

## 二、索引

| ID | 规则 | 当前语义 | 归属 | 单一事实源 |
| --- | --- | --- | --- | --- |
| C-1 | 任务区不出现外部仓库实名 | `.tasks/` 内指称外部仓库一律用通用措辞（「接入方仓库」「被参考仓库」等），不得写实名 | common | [common.md](./common.md) |
| C-2 | 路径书写与归档归一 | 仓库内引用用仓库根相对路径；任务进行中可留本机资源路径，归档时归一为 `<本机>/…`、`~/` 或 `%USERPROFILE%` | common | [common.md](./common.md) |
| C-3 | 技能命名与技能集定位 | 新建技能时：三段式 `fxri-<领域>-<形态>-<主题>`，主题不得与领域段、形态段重复或为空泛词，一技能一主题 | common | [common.md](./common.md) |
| C-4 | 分类归属按实践领域 | 归领域时：看这个技能主要在什么领域解决任务，交付物只作辅助判据；空领域只登记不进导航 | common | [common.md](./common.md) |
| C-5 | 取材边界 | 提炼技能时：只取用户点选的条目，不按「同族」自行扩入；索引只有标题须回详情文件读正文 | common | [common.md](./common.md) |
| C-6 | 分层与按需取用 | 写技能时：正文只放原则，组件与工具细节进适配表；每条带适用前提与跳出口径，不得要求新建替代物 | common | [common.md](./common.md) |
| C-7 | 描述与触发 | 写技能描述时：写全做什么 / 何时用 / 不涉及什么，声明依赖缺失时跳过，触发词覆盖近义表达 | common | [common.md](./common.md) |

## 三、用法说明

- **载体形态**：本项目采用「条文式」，条文全文落在本载体分册，本载体即项目唯一规范载体。
- **本项目约定**：单端项目（任务 `scope` 取值 `playbook`），规范全归 `common`，不设端分册与分类标签分册。
- **与技能的关系**：本载体是提炼技能时的唯一判据来源；技能正文与本载体冲突时，以本载体为准并同批修正技能。
- **读写与维护**：读面与读写判定、写入归属、语义修订与退休流程一律见全局技能 `fxri-plan-to-task` 的 conventions-spec，本载体不另述。
