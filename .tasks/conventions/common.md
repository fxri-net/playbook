# 全端通用规范（common）

> 归属：common（所有端适用）。条文全文见本节，索引见 index.md。

## C-1. 任务区不出现外部仓库实名

`.tasks/` 内文本指称本仓以外的仓库时，一律用通用措辞，不得写实名。

- **要求**：任务档正文、归档叙述与 frontmatter 字段值凡需提及本仓以外的仓库，须改用「接入方仓库」「被参考仓库」「外部仓库」这类通用称谓；做技术验证或对照参考时同样只写泛称，不得列举被参考对象的实名清单。判据取**是否以具体名称指涉某个外部仓库**，与 `C-2` 的路径判据正交；依赖包名、被调接口名等本仓事实照写。
- **反例**：在背景或归档叙述里列出下游仓库实名，或把实名当作 frontmatter 字段的示例值。本仓文本随 git 分发后即携带外部仓库的目录命名，而读者只具本仓视角、无从判断该名与本仓的关系。
- **理由**：任务区是仓库自述面，只承载本仓事实；实名指涉外仓既污染本仓文本，又把某次会话偶发的参照对象固化成仓库事实，还随分发外泄无关仓库信息。
- **配套**：与全局技能 `fxri-plan-to-task` 的 task-spec 中「跨仓库改动各自归档」配套——该纪律管「记不记他仓的事」（视角），本条管「写不写他仓的名」（用词），两者同属任务区文本治理。该纪律已在全局层承载，本载体不另立条文。

## C-2. 路径书写与归档归一

仓库内引用用仓库根相对路径；本机绝对路径只允许存在于进行中的任务档，归档时须归一为占位形式。

- **要求**：仓库内引用一律用以仓库根为基准的相对路径（含行号时形如 `src/cli.ts L103`），不得写指向本机的绝对 `file:///` 链接。分两阶段：任务进行中可保留需要以绝对路径索引的本机资源路径（设计素材、仓库外规则文件、本机解释器），便于当场定位；**归档时须归一**为占位形式——仓库外文件 `<本机>/…`、家目录 `~/` 或 `%USERPROFILE%`，仅保留可辨识的末段文件名。
- **反例**：在任务档写入本机解释器的完整安装路径后直接归档。该路径对他人不可用，且暴露作者本机的软件安装布局。
- **理由**：本机绝对路径随 git 分发后对他人无意义，且泄露作者本机目录结构。两阶段口径保留「进行中当场可定位」的便利，同时把泄露面收敛在未归档的临时文本里。
- **配套**：归一属归档写入时的形态处理，不构成对已归档块的追改；归档后发现遗漏的，按全局技能的「事实更正」通道追加修订记录。

## C-3. 技能命名与技能集定位

本集为综合实践技能集，技能按使用场景分类承载，不按技术领域各自占号；技能名即安装引用的唯一键。

- **要求**：命名三段式 `fxri-<分类>-<类型>-<主题>`——分类段取 `categories.json` 的 id 且与 frontmatter `category` 一致；类型段取 `scripts/validate.mjs` 的类型枚举（`bundle` / `template` / `profile` / `preset` / `guide`）；主题段为具体能力词，1–2 段。**主题段不得为领域大词**（`ui` / `data` / `web` / `app` / `frontend` / `engineering`），也不得以领域大词单独占据命名空间；领域级能力须先新增分类并单独论证。**一技能一主题**：主题扩张时拆新技能，不把不相关能力塞进同名技能。**存量旧名不改名**：改名破坏安装引用，门禁只校验新增技能。
- **反例**：`fxri-ui-restore`、`fxri-data-profile` 这类以领域大词作首段或主题的命名——单个技能宣称整个领域，后续同类能力无处安放，只能塞进既有技能或再造一个更大的词。
- **理由**：分类段是第一层可见信号，使用者按分类找能力；领域级命名会把「综合分类」压缩成「单个技能的领地」，而技能名一旦发布即被安装引用绑定，事后改名成本极高。
- **配套**：门禁实现见 `scripts/validate.mjs`（按 git 基准只校验新增技能）；分类归属判据见 `C-4`。

## C-4. 分类归属按使用场景

分类是使用场景的划分，不是被处理对象的领域划分。

- **要求**：**判据两条**——技能在哪个分类的场景里被使用；产出什么形态的交付物。不看被处理对象的领域。**称谓来源**——角色与场景称谓一律取该分类在 `categories.json` 的 `label` 与 `description`，不新造职业称呼；边界描述统一用「该分类的使用者」「该分类的交付物」表述。**交付物判据**——可运行实现归 `dev`；设计物料（视觉稿、交互稿、设计规范）归 `design`；文档与报告归 `writing` / `research`；数据产物、办公产物、环境变更各归其分类，以 `categories.json` 的 description 为准。**跨场景能力**按主要使用场景归属，不为次要场景新开分类；新增分类须同时写明使用者与交付物，否则不得启用。**一次定对**——分类 id 即技能名首段，改名破坏安装引用，归属须在新建时定准。
- **反例**：按被处理对象归类——「按设计稿实现页面、还原与核对验收」因对象是设计稿而被归入 `design`，与真正使用该技能的执行场景不符。
- **理由**：按对象领域归类会让同一执行场景散落到多个分类，使用者按分类检索时反而找不到；交付物形态比岗位称谓稳定，跨团队、跨分类都能对齐。
- **配套**：与 `C-3` 配套——`C-3` 管名字形态，本条管分类归属；分类清单与状态见 `docs/categories.md`。
