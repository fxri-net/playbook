# 修复门禁行尾误报

批次：本仓本轮门禁与 CI 收敛第 2 项（前置：无；执行第 1 项时发现）

## 背景

执行「CI 补手动触发」时 `node scripts/verify.mjs` 在「结构校验」步骤失败，报 5 项 catalog 不一致（`catalog.md`、`docs/catalog.md`、`docs/sidebar.json`、两篇技能页）。运行 `node scripts/gen-catalog.mjs` 重新生成后，`git diff` 无内容差异，且 `git hash-object` 与 `HEAD` 对应 blob 完全一致——说明**内容本来就一致，差异只在行尾**：Windows 检出（`core.autocrlf=true`）把生成物转成 CRLF，而 `validate.mjs` 用 `readFileSync(...) !== 期望字符串` 做逐字节比对，期望值是生成脚本产出的 LF。

后果：本仓在 Windows 上跑门禁必然假红，Linux CI 却是全绿——属「门禁与环境相关」，与既有规范「验收须与运行环境无关」冲突。

## 实施方案

1. `scripts/validate.mjs` 增加 `readNormalized(file)`：读文本后去 BOM、把 CRLF 归一为 LF。
2. 四处生成物比对（`catalog.md`、`docs/catalog.md`、`docs/sidebar.json`、`docs/skills/*.md`）改用该函数，其余校验逻辑不动。
3. 不改生成脚本产出的行尾，也不引入 `.gitattributes` 强制转换——比对层归一即可，对 Linux CI 与 Windows 本地同时成立。
4. 不建变更集：校验脚本改动，用户不可感知。

## 影响范围

- 代码：`scripts/validate.mjs`（新增一个本地函数 + 四处调用替换）。
- 无触达：技能内容、生成物、手写文档、`README.md`、CI 配置。
- 变更集：不建（用户不可感知）。

## 验证方式

- Windows 本地 `node scripts/validate.mjs` 通过（修复前对同样内容报 5 项）。
- 反向验证：故意改动 `catalog.md` 一行内容后重跑，仍必须报不一致，确认归一没有放过真实漂移。
- `node scripts/verify.mjs` 全绿（归档后复跑）。

## 实施结果

- `scripts/gen-catalog.mjs`：`buildSkillPage` 嵌入正文前把换行归一为 LF——根因是 Windows 检出的 SKILL.md 为 CRLF，直接嵌入会让生成页混入 CRLF，与比对期望不一致（仅改比对层不够，期望侧本身也带 CRLF）。

# CI 补手动触发

批次：本仓本轮门禁与 CI 收敛第 1 项（前置：无）

## 背景

GitHub Actions 平台故障期间会出现「推送成功但没有产生任何运行」的情况（平台侧丢事件），而本仓工作流只有 `push` / `pull_request` 两种触发方式，缺手动入口，只能等下一次推送。补 `workflow_dispatch` 后可从 Actions 页面或 API 手动补跑，不污染提交历史。

本仓的文档部署是 `ci.yml` 内的 `deploy` job，补在 `ci.yml` 即覆盖「验收」与「部署」两条链路，无需新增文件。

## 实施方案

1. `.github/workflows/ci.yml` 的 `on:` 下增加 `workflow_dispatch:`（与 `push` / `pull_request` 并列），附一行中文注释说明用途。
2. 不动 jobs、权限、步骤与部署条件；`deploy` job 的 `if` 已限定 `github.event_name == 'push'`，手动触发只跑验收、不会误部署。
3. 不建变更集：CI 配置不随包分发，用户不可感知。

## 影响范围

- 代码：`.github/workflows/ci.yml`（一行触发器声明）。
- 无触达：技能内容、手写文档、`README.md`、门禁步骤清单。
- 变更集：不建（用户不可感知）。

## 验证方式

- `git diff` 确认只新增触发器声明，其余内容未变。
- 推送后 Actions 页面出现「Run workflow」入口，且手动触发时 `deploy` job 按 `if` 条件跳过。
- `node scripts/verify.mjs` 全绿（归档后复跑）。

## 实施结果

- `.github/workflows/ci.yml` 的 `on:` 增加 `workflow_dispatch:` 并附注释，`push` / `pull_request` 原样保留；jobs、权限与 `deploy` 的 `if` 条件未动。
- 手动触发时 `deploy` job 因 `github.event_name == 'push'` 不成立而跳过，只跑验收。
- 未建变更集（CI 配置不随包分发）。
- 验证命令：`node scripts/verify.mjs` 全绿（归档后复跑）。
