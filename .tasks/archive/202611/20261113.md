# 统一 CI 结构：拆分部署工作流并统一任务名

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

本仓是七个仓中唯一把文档部署写在 `ci.yml` 里的：`ci.yml` 同时承载 `verify` 与 `deploy` 两个 job，且部署把 build、上传、发布压在一个 job 内。其余六仓均为「`ci.yml` 只放门禁」+「`deploy-docs.yml` 独立、build 与 deploy 分两个 job」。结构不一致会让改动时容易漏改，也让「文档构建只出现在部署工作流」这条口径无法逐仓核对。

## 改动

1. `ci.yml`：job `verify` 更名为 `check`（与其余仓一致）；删除 `deploy` job 及其 `permissions` / `environment` 配置；顶部注释去掉「deploy job 的 if 已限定 push」。
2. 新增 `deploy-docs.yml`：`push` 到 main 与 `workflow_dispatch` 触发，`permissions` 与 `concurrency` 与其余仓同形，`build` job 负责构建与上传产物，`deploy` job 负责发布。
3. GitLab 侧不动：本仓使用固定镜像而非 `ci-templates` 动态镜像，属基础设施差异，不在本次范围。

## 影响范围

- GitHub 侧：门禁与部署彻底分离，部署不再依赖 `verify` job（原先靠 `needs: verify`，现由两个工作流各自独立触发）。
- 站点构建参数不变（`docs:build`，base 由 `config.mts` 默认值与 `DOCS_BASE` 决定）。

## 验证方式

- 两个工作流 YAML 经解析器校验可解析。
- `node scripts/verify.mjs` 全绿。
- 推送后分别确认 CI 与 Deploy Docs 两条流水线均触发成功。

> 计划位置：第 1 个（共 1 个）；前置：toolkit 1.16.12；后继：无

## 背景

3. `config.mts`：改为 `import siteNav from '../site-nav.json'`，去掉运行时读文件。
4. `verify.mjs`：主题 / 导航 / 产物三步改调 `node scripts/toolkit.mjs docs <对象> check`（全局工具缺失时由包装脚本打印跳过）。
5. 删除 `scripts/check-docs-nav.mjs`、`scripts/check-docs-dist.mjs`、`docs/sidebar.json`；同步 AGENTS.md 与 CONTRIBUTING.md 的生成物清单。
