# 修正变更基准判定

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

本地按「归档 → 验收 → 提交」执行时，提交后复跑 `node scripts/verify.mjs` 会误报「本次改动触及技能 / 手写文档 / 清单 / 生成脚本，须新增变更集」，即使变更集已在同一批提交里新增。

根因在 `scripts/validate.mjs` 的本地基准：无 CI 环境变量时退回 `git rev-parse HEAD~1`，它只看最后一条提交。一个批次跨多条提交时（如先提交技能与变更集、再提交任务归档），基准落在批次中间，`git diff` 仍能看到后续提交里的技能改动，而 `git log --diff-filter=A baseline..HEAD` 看不到基准提交自身新增的变更集，于是判定为缺失。本次用 `CHANGESET_BASE_REF=0f1b827` 手工指定变更前提交才通过，属可复现的误报。

## 实施方案

1. `scripts/validate.mjs` 的基准链在 `HEAD~1` 之前插入「本地上游分叉点」：取 `@{upstream}` 与 `HEAD` 的 merge-base，覆盖未推送的整批提交；无上游时保持 `HEAD~1` 兜底。
2. 同步更新基准链注释与 `AGENTS.md` 的「git 基准」条目。
3. 不改 `verify.mjs` 步骤清单，不改技能内容，不升技能版本。

## 影响范围

- 代码：`scripts/validate.mjs`。
- 文档：`AGENTS.md`（git 基准列表）。
- 变更集：无（不在 AGENTS 列举的变更集触发面内）。
- 技能：无改动（`skills/` 未变，版本不动）。

## 验证方式

1. 复现原场景：改动已提交、工作区仅剩任务归档差异，不带 `CHANGESET_BASE_REF` 跑 `node scripts/validate.mjs`，应由失败转为通过。
2. `node scripts/verify.mjs` 全量通过。
3. `toolkit task check` error 与 warn 均为 0。

## 回滚

单提交回退：删除上游分叉点分支、还原注释与 AGENTS 条目。
