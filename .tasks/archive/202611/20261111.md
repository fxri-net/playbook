## 实施方案

1. `.tasks/conventions/common.md` 新增两条条文：
   - C-3 技能命名与技能集定位：三段式 `fxri-<分类>-<类型>-<主题>`，分类取 categories.json 的 id，类型取 validate 的类型枚举，主题为具体能力词；主题不得为 ui / data / web / app / frontend / engineering 等领域大词；一技能一主题；存量旧名不改名。
   - C-4 分类归属按使用场景：判据为「在哪个分类的场景里被使用 + 产出什么形态的交付物」，不看被处理对象的领域；角色与场景称谓一律取该分类的 label 与 description，不新造岗位名；跨场景能力按主要使用场景归属；新增分类须同时写明使用者与交付物。
2. `.tasks/conventions/index.md` 索引表新增 C-3、C-4 两行，归属 common，单一事实源 `common.md`。
3. `AGENTS.md` 协作流程约束新增一条「新建技能须符合 conventions 的 C-3 / C-4」，并同步更新首部规则更新时间。
4. `CONTRIBUTING.md` 新增技能命名规则由 `fxri-<分类>-<名称>` 细化为三段式，写明分类段与类型段的取值来源、主题段禁用领域大词。
5. `docs/contributing.md` 同步手写镜像内容。
6. `docs/categories.md` 补充分类 id 即技能名首段、交付物判据，以及新增分类须写明使用者与交付物的前置要求。
7. `README.md` 第 12 行定位由「面向 AI 协作的工程规范集」改为「面向 AI 协作的综合实践技能集」，第 14 行「工程经验」改为「实践经验」。
8. `scripts/validate.mjs` 新增命名校验：取 git 基准（沿用文件内既有 getBaseline 机制），只校验基准之后新增的技能名，须匹配 `fxri-<category>-<type>-<主题>`，且主题段不含领域大词；无基准时打印「跳过（无 git 基准）」，不静默放行。
9. `.changeset/` 新增 patch 变更集，条目逐条以 `- 类型：描述` 书写。

## 影响范围

- 文档触达：.tasks/conventions/index.md、.tasks/conventions/common.md、AGENTS.md、CONTRIBUTING.md、docs/contributing.md、docs/categories.md、README.md、package.json、scripts/validate.mjs

## 验证方式

- `node scripts/verify.mjs` 全绿；`toolkit tasks check` error 0 且 warn 0。
- 门禁自检：临时用非法技能名触发一次校验确认能拦下，确认后立即还原，不保留临时改动。
- 复核 docs/contributing.md 与 CONTRIBUTING.md 内容一致，docs/categories.md 与 categories.json 描述不冲突。
