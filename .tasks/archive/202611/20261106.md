## 背景

分类骨架、命名上限、顶栏规范与校验口径目前只写在七份仓库任务档里，归档后虽可检索，但新仓库与新页面没有稳定的引用源。playbook 是「方弦实践集」规范仓，把这份跨仓标准沉淀为可分发档案（skill），后续直接按触发加载，不再依赖任务档。

## 实施方案

1. 新增 `skills/fxri-docs-profile/SKILL.md`：frontmatter `name` / `description` / `metadata`（`version: "0.1.0"`、`tier: optional`、`category: writing`、`type: profile`、`triggers` 覆盖文档站导航、分类命名、侧栏与顶栏规范）；正文首部双写版本号。
2. 技能正文固化以下条款：
   - 分类骨架：开始 / 指南 / 参考 / 原理 / 升级 / 开发 / 帮助，另有「技能」「档案」等领域组；按仓库裁剪。
   - 命名上限：分组名 2 字优先、最长 4 汉字；纯页面条目豁免，分组名不豁免。
   - 顶栏规范：一级项 ≤5；首项「快速开始」直链、末项「帮助」；下拉 2–8 项；单页不做单项下拉；禁用 `FAQ` 等缩写；更新日志、常见问题、贡献指南统一进「帮助」。
   - 扩展规则：新页面优先并入现有分组；升级族按 `upgrade-<major>/` 独立目录；分组超过 8 项再拆二级组（组名同样 ≤4 字）。
   - 术语固定：快速开始（替代新手指南 / 快速上手）、操作手册（场景步骤）、完整攻略（解释型长文）、参考（查询型分组）、常见问题（替代 FAQ）、更新日志、贡献指南、接入；各仓不得自造近义词。
   - 兜底页：每站提供 `docs/404.md`（首页、常见问题、更新日志入口 + 搜索提示），旧 URL 不重定向但可继续导航。
   - 体量预警：单页 >300 行（排除 `changelog.md` 镜像）在 verify 输出 warn，只提示不阻断。
   - 校验规则：按规则实现（项数、首项与末项、帮助必备项、字数、链接可达、禁用缩写），不维护页面白名单；toolkit 并入现有文档一致性测试，其余仓库用 `scripts/check-docs-nav.mjs`。
   - 变更与兼容：旧 URL 接受 404、不做重定向页；文档导航类变更统一按 patch 变更集记录。
   - 触发词粒度：只收具体组合（「文档站分类」「导航规范」「侧栏命名」「顶栏规范」「文档站命名」），禁止「文档」「导航」等单字泛词，避免普通写作任务误加载。
   - 真源模型：本档案为规则唯一真源；各仓以 `scripts/check-docs-nav.mjs` 作可执行投影（脚本头注释标注来源与版本），任务档保留本仓适用的可执行摘要（允许重复关键约束），并在计划位置登记所依据的规范版本。单仓无档案时以脚本与摘要执行；接触档案后发现不一致，以档案为准并同批修正投影。
3. `skills.json` 新增条目：`fxri-docs-profile`、`path: skills/fxri-docs-profile`、`category: writing`、`type: profile`、`version: 0.1.0`、`requires: []`。
