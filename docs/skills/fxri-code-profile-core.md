# 编码核心规范

> 技能：`fxri-code-profile-core`　类型：profile　版本：0.1.0

# 编码核心规范

> 本技能版本 0.1.0（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 同一能力在多个面重复出现，需要判断「统一到什么层级」时
- 设计或评审契约、真源、交互基座、展示基建、输出通道时
- 出现两种相反倾向：为一致而一致，或每个面各写一套时

不涉及：语言、框架、组件与工具的具体写法（见各分端 profile）；视觉与交互设计本身。

## 通用说明

本技能是跨端核心层：只放与语言、框架无关的取舍准则，不复制分端规范。规则按编号追加，每条写明适用前提、从权边界与反例。

## 规则

### 1. 架构统一与表达从权

- **适用前提**：同一能力在多个面（命令、页面、交互、输出）重复出现，或需要决定是否复用既有基座。
- **要求**：统一在架构层——契约、真源、交互基座、展示基建、输出通道必须只有一个 owner；表达层可从权——截断方式、折叠阈值、名称长短、路径省略位置等按场景取最优。
- **做法**：先查既有规范与真源能否承载；不能承载时先补基座或真源，再在基座提供的参数内做场景化选择。偏离基座默认行为时，在任务档或代码注释写明理由。
- **从权边界**：不改对外契约；不产生第二套实现；不新增只为单场景服务的开关；宁可局部保留差异，也不把无关场景耦合成一套配置。
- **反例（过度统一）**：让所有答案行格式完全一致，连升级项也截断标识导致信息丢失；为单场景在基座上加开关，其它调用方被迫理解无关参数。
- **反例（过度分散）**：每个面自写一份截断、着色或真源读取，用「场景不同」解释重复实现。
- **理由**：过度统一把偶合变成依赖，完全分散回到重复实现；分层统一让一致性落在契约与真源上，把表达自由留给使用面。

## 检查清单

- [ ] 契约、真源、基座、输出通道只有一个 owner
- [ ] 表达差异限定在基座提供的参数内
- [ ] 偏离基座默认行为已写明理由
- [ ] 未为单场景新增基座开关
- [ ] 未自写第二套截断、着色或真源读取
