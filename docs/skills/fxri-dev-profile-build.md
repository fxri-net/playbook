# 构建与质量规范

> 本技能版本 0.1.0（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 处理构建告警、循环依赖告警、代码生成物差异
- 调整质量门强度、本地与流水线的判定口径
- 接口由契约生成，需要确定手工层与生成层的边界

不涉及：代码组织约定（见 `fxri-dev-profile-web`）、接口数据的呈现（见 `fxri-dev-profile-display`）。

## 通用说明

每条规则带「适用前提」与「项目无对应物」两段，前提不成立即整条跳过。工具钩子、生成器命令与流水线变量见 [适配表](https://github.com/fxri-net/playbook/blob/main/skills/fxri-dev-profile-build/./references/adapters.md)，示例与反例见 [原则示例](https://github.com/fxri-net/playbook/blob/main/skills/fxri-dev-profile-build/./references/principles.md)。

## 规则

### 1. 构建告警按来源归属治理

- **适用前提**：构建过程输出告警。
- **要求**：自身源码触发的告警一律改写法消除源头，不套过滤；依赖包触发的告警才允许按告警码精准过滤，不整级压低日志级别。验收以复跑构建后告警检索归零为准，不以编译通过替代——告警不阻断编译，通过不代表已消除。
- **项目无对应物**：构建工具不提供按告警码过滤的能力时，只做源头治理，并在任务档记录无法过滤的告警码。
- **反例**：把自身代码的告警一并过滤；用编译成功代替告警归零。

### 2. barrel 成员不得回引自身

- **适用前提**：项目有聚合导出文件（barrel）与路径别名。
- **要求**：被聚合导出的成员文件不得经聚合入口回引自身，成员侧一律直连具体文件。断边前核验目标文件的导出形态与相对路径层级，防止经二级文件再次绕回；聚合文件之间互指时，须把一侧的全部成员改为直连。
- **项目无对应物**：项目无聚合导出时整条不适用。
- **反例**：成员继续用别名导入聚合入口；断边后导出形态不匹配；只改一处、另一侧仍成环。

### 3. 质量门零告警

- **适用前提**：项目有本地与流水线共用的聚合验收命令。
- **要求**：静态检查的告警与错误一并令验收非零退出，不按级别分级放行；本地执行前先对改动文件自动修复可修项，再据结果判定；流水线判别使用流水线专用环境变量，不用通用 CI 变量（本地终端也可能为真，会误判并关停自动修复）。
- **反例**：靠逐条提级规则来拦住告警；用通用 CI 变量判别流水线。

### 4. 接口契约生成优先

- **适用前提**：接口类型与调用由契约工具生成。
- **要求**：接口优先由契约生成；契约未收录的实现可暂由手工层承接，但须登记并推动补入契约，补入后迁移到生成层并删除手工实现；生成层须复用统一的请求实例与拦截器，新旧接口使用同一套响应类型；生成物不得手改，契约缺失回上游补；生成后跑验收并至少实测一个真实调用点，生成成功本身不构成验收。
- **项目无对应物**：项目无契约生成链路时，手工接口集中在单一入口维护，并登记待迁移清单。
- **反例**：契约已收录仍手工重复实现；长期留在手工层不登记；直接改生成文件补字段；生成接口另建请求实例导致鉴权与错误提示失效。

## 检查清单

- [ ] 自身源码告警已改写法消除，仅依赖包告警被过滤
- [ ] 验收以告警检索归零为准，未用编译通过替代
- [ ] 聚合导出成员均直连具体文件，无二级绕桶
- [ ] 质量门告警与错误一并阻断，本地先自动修复
- [ ] 生成物未手改，手工层已登记并迁移
- [ ] 生成后实测过至少一个真实调用点
