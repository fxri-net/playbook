# 服务端开发规范

> 本技能版本 0.1.0（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 设计或评审后端接口、服务边界与数据一致性
- 处理重复请求、事务、重试与故障隔离
- 线上排障需要补日志、指标与链路信息

不用于：前端实现、框架语法教学、纯数据库调优。

## 八条核心原则

1. **契约先行**：接口的入参、出参、错误码与状态码先定义再实现；变更须评估兼容性并留迁移窗口。
2. **入口校验**：所有外部输入在边界处校验类型、范围与权限；内部调用不重复做边界校验。
3. **写操作幂等**：创建、支付、消息消费等可重试写操作必须有幂等键或去重机制。
4. **事务边界清晰**：一个事务只包住必要的写；跨服务一致性用补偿或最终一致，不假设分布式事务。
5. **可观测性内建**：关键路径有日志、指标与链路标识；日志带请求 ID，不打印敏感字段。
6. **安全默认**：最小权限、参数化查询、输出编码；凭据只来自环境或密钥管理，不落代码与日志。
7. **故障隔离**：外部依赖有超时、重试上限与熔断；失败可降级，不把单点故障扩散成全站不可用。
8. **文档随代码**：接口文档、错误码表与运行手册与实现同批更新；文档过期视为缺陷。

## 工作流程

1. 先写契约与错误码，再写实现与测试。
2. 为写操作补幂等与并发用例，为外部依赖补超时与失败用例。
3. 上线前确认日志、指标、告警与回滚路径。
4. 变更契约时同步文档与调用方，保留兼容窗口。

## 检查清单

- [ ] 入参、出参与错误码已定义且与实现一致
- [ ] 外部输入在边界校验，权限检查不可绕过
- [ ] 可重试写操作具备幂等键
- [ ] 事务只包含必要写操作，跨服务有一致性方案
- [ ] 关键路径有日志 / 指标 / 链路标识
- [ ] 外部依赖有超时、重试上限与降级
- [ ] 凭据不在代码、配置明文或日志中
- [ ] 接口文档与错误码表已同步
