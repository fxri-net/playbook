# 前端通用规范

> 本技能版本 0.2.1（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 需要约定前端工程的共享工具命名、注释组织、函数排序时
- 需要按设计稿识别页面内容、排除宿主框架性头部时
- 与 Vue / 具体框架无关的通用前端约定

不涉及：格式化、状态三分类、Defines / AxiosParse、SFC 语法与 JSDoc 语法（见 `fxri-dev-profile-vue`）。

## 规则

### 1. 共享工具函数前缀

- **要求**：共享工具函数的前缀始终跟随项目里已有的前缀，不另起一套。
- **做法**：项目已有 `fxXxx` 这类统一前缀时，新增共享工具沿用同一前缀风格。
- **反例**：项目共享工具统一以 `fx` 开头，新增工具却另起一套前缀，导致同一类工具出现两套入口。

### 2. 逐变量注释

- **要求**：每个变量单独写简短注释，不把多个变量挤在一行注释里。
- **做法**：注释紧贴变量所在行或上方，说明该变量承载什么。
- **反例**：`// 用户与订单数据` 一行注释覆盖两个不同变量，后续无法判断注释对应哪一个。

### 3. 注释讲「为什么」

- **要求**：行内注释解释为什么这样写，而不是复述代码在做什么。
- **做法**：在分支、兼容处理、特殊取值处说明原因与约束。
- **反例**：`// 赋值给 a` 这类只复述动作的注释。

### 4. 统一用词

- **要求**：描述动作与结果时统一使用「疏理」「配置」「返回」「校验」等既有用词，不混用近义词。
- **做法**：同一类操作在注释、文档与命名说明中保持同一动词。
- **反例**：同一项目中「整理 / 疏理 / 梳理」混用，「校验 / 验证 / 检查」混用。

### 5. 函数名按英文首字母排序

- **要求**：同一文件内的函数按函数名英文首字母排序。
- **做法**：如 `doBase → doData → doDom → doInfo → doOption → doParam → doRoute → doSafe → doSite → doUser`。
- **反例**：函数按编写时间或调用顺序随意排列，新增函数插在中间导致顺序持续漂移。

### 6. 效果图识别

- **要求**：识别 UI 效果图时忽略非页面内容本身的框架性头部。
- **做法**：忽略系统状态栏（时间、信号、网络、电量）与宿主容器 / 应用导航栏（返回、标题、窗口控制按钮），只识别其下方真正的页面内容。
- **反例**：把手机状态栏或宿主应用标题栏当成页面组件实现。

## 检查清单

- [ ] 共享工具函数沿用项目已有前缀
- [ ] 每个变量有独立简短注释
- [ ] 行内注释解释「为什么」
- [ ] 动词用词统一
- [ ] 函数按英文首字母排序
- [ ] 设计稿只还原页面内容，忽略宿主框架性头部

详细示例与反例见 `references/principles.md`。
