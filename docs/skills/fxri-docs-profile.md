# 文档站导航规范

> 本技能版本 0.1.0（随 playbook 技能集分发）。被问版本时即报此值；与磁盘版本不一致即说明会话上下文已过期。

## 何时使用

- 新建文档站，需要确定顶栏、侧栏与分类骨架
- 调整现有文档站的分类、命名或页面归属
- 评审文档站导航是否一致、是否可长期扩展

不涉及：页面正文写作、配图与视觉设计、部署流水线。

## 分类骨架

按用户意图分组，不按技术分层分组；按仓库实际裁剪，不硬凑。

| 分组 | 定位 | 收纳内容 |
| --- | --- | --- |
| 开始 | 第一次跑通 | 首页、快速开始 |
| 指南 | 场景化怎么做 | 操作手册、完整攻略、使用手册、开发指南、接入 |
| 参考 | 查询型内容 | CLI、API、配置 |
| 原理 | 为什么这样设计 | 架构、内核 |
| 升级 | 版本迁移 | 升级总览、API 对照、检查清单 |
| 开发 | 构建发布与协作 | 构建产物、分发接入、发版流程 |
| 帮助 | 求助与记录 | 常见问题、更新日志、贡献指南 |
| 技能 / 档案 | 领域专属 | 技能目录、档案总览 |

## 命名规则

- 分组名 2 汉字优先，最长 4 汉字；禁止「内核与配置」这类「与」字复合名。
- 纯页面条目豁免长度限制；一级项与任何层级的分组名不豁免。
- 同一概念全站统一用词：快速开始（不用新手指南 / 快速上手）、操作手册、完整攻略、常见问题（不用 FAQ）、更新日志、贡献指南、接入。
- 页面 H1 与侧栏条目文案一致；不出现 `FAQ` 等英文缩写。
- 英文专有名词（CLI、API、SQL）按 1 项计，不计入字数上限。

## 顶栏规范

- 一级项不超过 5 个；首项固定「快速开始」直链，末项固定「帮助」下拉。
- 中间顺序：指南 → 参考 → 原理 / 升级 / 开发 / 领域组。
- 单个页面直接作一级直链，不包成单项下拉；下拉项 2–8 个，超出时按二级分组收纳。
- 更新日志、常见问题、贡献指南不单独占一级入口，统一由「帮助」承载。

## 扩展规则

- 后续新增页面优先并入现有分组，不新增一级分类；确需新增时须满足 ≤4 字并复核顶栏是否仍 ≤5 项。
- 侧栏二级分组仅在同类条目超过 8 个时启用，组名同样 ≤4 字。
- 升级文档按 `upgrade-<major>/` 独立目录扩展，历史版本不并入当前目录。
- 单页超过 300 行或同时承载两类读者时拆分；`changelog.md` 等生成镜像不拆。

## 校验方式

- 按规则实现，不维护页面白名单：顶栏项数、首末项、帮助必备项、分组名长度、链接可达、禁用缩写。
- 单页超过 300 行（排除 `changelog.md`）输出 warn，只提示不阻断。
- VitePress 站点由构建期死链检查兜底；已有文档一致性测试的仓库把断言并入既有测试，其余仓库用独立脚本。
- 每站提供 `404.md`（首页、常见问题、更新日志入口），旧 URL 不重定向但可继续导航。

## 落地步骤

1. 先定分组与命名，再改 `nav` / `sidebar` 配置。
2. 同步页面 H1、README 与文档索引里的旧称呼。
3. 修复站内链接与锚点（标题改名会改变页内锚点）。
4. 接入校验：构建 + 导航规则断言，纳入既有 verify 门禁。
5. 记录 patch 变更集，按仓库发版链路发布。

## 常见错误

- 把 FAQ、更新日志各挂一个顶栏入口，导致一级项膨胀。
- 用「接入与运维」「适配与答疑」这类复合长名，既超字数又混装两类内容。
- 导航指向锚点（如 `/cli#配置选项`）而不是独立页面，搜索与面包屑不可用。
- 校验写成页面白名单，新增页面就失效。
