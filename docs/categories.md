# 分类说明

分类即**实践领域**，用于组织技能，不创建空技能目录。领域 `id` 即技能名首段（`fxri-<领域>-<形态>-<主题>`）。

> 边界说明：技能分类与文档站导航分组是两套互不约束的词汇。技能分类回答「这个技能属于哪块实践」，导航分组回答「这页文档放在站内哪个位置」，两者不互相引用、不同批修改。

## 归属判据

- 看「这个技能主要在什么领域解决任务」，不看职能、介质或来源。
- 交付物形态只作辅助判据：两个领域都说得通时，用「主要产出什么」裁决。
- 跨领域能力按主要用途归属，不为次要用途新开领域。
- 空领域只登记、不进导航、不建目录。
- 新增领域须同时写清实践对象、典型任务，以及与既有领域的边界。
- 单领域技能超过 8 个时，按命名族沉淀或拆分领域。

## 领域清单

| 领域 | 名称 | 说明 |
| --- | --- | --- |
| `code` | 编码 | 软件实现、构建与工程化 |
| `writing` | 写作 | 书面表达与知识条目 |
| `research` | 研究 | 检索、分析与评估 |
| `design` | 设计 | 视觉、交互与版式 |
| `data` | 数据 | 数据处理、统计口径与可视化 |
| `office` | 办公 | 表格、日程与事务性工具 |
| `ops` | 运维 | 部署、发布与稳定性 |
| `life` | 生活 | 个人事务与日常安排 |
| `meta` | 元技能 | 技能、规则与协作机制 |

只有已有技能的领域会出现在技能目录与侧边栏；空领域仅在此登记，防止未来重名。

## 技能形态

形态是二级分类，写在技能名第二段，与 frontmatter `type` 一致：

| 形态 | 名称 | 判据 |
| --- | --- | --- |
| `profile` | 规范 | 约束「怎么做」，以条文、检查清单、反例承载 |
| `practice` | 流程 | 规定「按什么步骤做」，以工作流与分支判定承载 |
| `template` | 模板 | 可直接套用的文件骨架或配置集 |

分类与命名体系变更时的升级动作见 [0.3.0 迁移说明](./migrations/0.3.0.md)。
